# <img src="https://api.iconify.design/selfhst:last-fm.svg?color=f8211c" width="24" height="24" alt="Last.fm icon"> Releasing

Releases are built by GitHub Actions from version tags. Local credentials and
build outputs stay outside the tracked source tree.

## <img src="https://api.iconify.design/selfhst:last-fm.svg?color=f8211c" width="20" height="20" alt="Last.fm icon"> Before tagging

```bash
test -z "$(gofmt -l .)"
go test ./...
go test -race ./...
go vet ./...
go build -buildvcs=false ./cmd/scrobbler
git diff --check
```

Confirm the working tree contains only intended source/docs/assets. `.env`,
credentials, `bin/`, `dist/`, logs, ZIP files, diagnostics bundles, font
archives, and temporary release output must not be tracked or staged. Never
create a public source ZIP by archiving the working directory directly; use
GitHub's tracked source archive or `git archive`.

## <img src="https://api.iconify.design/selfhst:last-fm.svg?color=f8211c" width="20" height="20" alt="Last.fm icon"> Create a release

```bash
git tag -a v1.1.0 -m "v1.1.0"
git push origin v1.1.0
```

The tag-triggered workflow builds exactly these release targets:

```text
GOOS=darwin  GOARCH=arm64
GOOS=darwin  GOARCH=amd64
GOOS=linux   GOARCH=amd64
GOOS=linux   GOARCH=arm64
GOOS=windows GOARCH=amd64
```

Each target publishes its raw binary and archive:

```text
scrobbler-darwin-arm64
scrobbler-darwin-amd64
scrobbler-linux-amd64
scrobbler-linux-arm64
scrobbler-windows-amd64.exe
scrobbler-v<version>-darwin-arm64.tar.gz
scrobbler-v<version>-darwin-amd64.tar.gz
scrobbler-v<version>-linux-amd64.tar.gz
scrobbler-v<version>-linux-arm64.tar.gz
scrobbler-v<version>-windows-amd64.zip
checksums.txt
```

Every archive contains the platform executable, `LICENSE`, and non-empty
completion files for zsh, bash, fish, and PowerShell. Completion files are
generated by a host-native temporary binary, never by a cross-compiled
release executable. Unix archives contain `scrobbler`; Windows contains
`scrobbler.exe`.

Checksums are generated from inside `dist`, so every entry uses a release
basename. Do not checksum `checksums.txt` itself; after publishing, download
the assets into an empty directory and run `shasum -a 256 -c checksums.txt` or
`sha256sum -c checksums.txt`.

Release builds inject the tag version, exact commit SHA, and
`deathrashed/lastfm-scrobbler` repository into the existing version metadata.
The update checker uses the official GitHub Releases source by default;
`SCROBBLER_UPDATE_URL` is only needed for a custom endpoint.

## <img src="https://api.iconify.design/selfhst:last-fm.svg?color=f8211c" width="20" height="20" alt="Last.fm icon"> Installation paths

The public module path supports:

```bash
go install github.com/deathrashed/lastfm-scrobbler/cmd/scrobbler@v1.1.0
```

A Homebrew formula belongs in a separate `deathrashed/homebrew-tap` repository
and should be added only after stable published asset URLs and checksums are
verified.
